定稿日期：2026-10-20。产品与技术实现方案。先改规则与验收文档，再写代码。单人玩法、[rules.md](rules.md) 第 1–3 节、已冻结的第 0–2 期交接都不改。第 2.1 期上线交接继续开着，不冻结。

相关：[roadmap.md](roadmap.md)、[prd.md](prd.md)、[tech.md](tech.md)、[test.md](test.md)、[app-cross-platform.md](app-cross-platform.md) §5.1。

# 一、功能目标

两名玩家使用同一台设备，同时看一道 24 点。先想到的人点自己的「抢答」，取得答题权，并在限时内算完。

红方、蓝方是设备左右两侧的位置，不是固定的人。换边之后，历史统计不会跟着某个人走。

本期只做本地双人。不做联网、登录、匹配、好友邀请、排行榜、AI 对手、失败统计、回放和云同步。

核心流程：

```text
等待抢答
→ 第一位答题
→ 第一位失败后 3 秒交接
→ 第二位答题
→ 成功得分或双方失败
→ 下一局
→ 先到 5 分结束比赛
```

# 二、首页

四个同宽居中按钮，自上而下：

1. `单人游戏`：原来的「开始游戏」，仍是珊瑚主按钮。已有单人局时只重置当前题。
2. `双人对战`：蓝底白字。进入一场新的 `0 : 0`。
3. `游戏说明`
4. `设置`

两个游戏入口都解锁并开始背景音乐。说明页增加一段「双人对战」：先抢答，在设置的秒数内算出 24；第一位失败后换对方；先到 5 分获胜。不写减法和除法的点击顺序。

# 三、双人对战设置

双人难度、已玩题目、「含无解题」与单人分开保存，抽题算法相同。

1. 难度：简单、中等、困难、全部。在双人对战页等待抢答时修改，读写双人自己的难度。
2. 含无解题：同样只影响双人发牌。打开后每次发牌有 25% 抽无解题，有解池和无解池各自优先未玩。
3. 先到 5 分获胜：固定规则，不能改。

等待抢答时改难度或「含无解题」：

1. 立即重新抽取一道符合新设置的题。
2. 当前比分保持不变。
3. 不计成功或失败。
4. 重新进入等待抢答；当前题不可继续抢答。

倒计时答题中不提供难度与「含无解题」修改。

## 答题时长

设置页增加「双人对战答题时长」：

1. 默认 20 秒。
2. 范围 10 到 60 的整数秒。
3. 秒数左边减号、右边加号，每次加减 **5** 秒。结果夹在 10～60（例如 20 → 15 / 25）。到边界时对应按钮变灰或不响应。
4. 已经开始的倒计时沿用开始时的秒数。
5. 清缓存后恢复 20 秒。

# 四、对局页面

## 1. 基本布局

牌面仍是固定 2×2，合牌规则与单人相同。

**与单人相同的部分：** 底栏三段（答案 / 难度 / 设置）和底栏上方的「重试」「下一局」「本题无解」，位置与单人一致。双人只按状态显示或隐藏；「答案」在双人写成「显示答案」。

**双人多出来的部分：**

1. 牌正下方抢答区（固定预留两行高度，避免「点击认输」时运算符上下跳）：

```text
红方抢答       3 : 1       蓝方抢答
（预留提示）                 （预留提示）
```

   - 左红 `#E23B32`、右蓝 `#2F6FED`，白字；中间比分固定「红方 : 蓝方」，如 `3 : 1`。
   - 等待时提示行为空；答题时只在答题方下显示「点击认输」。隐藏一侧按钮时那一格留空。
   - 窄屏把该行算进高度；宽屏仍在左栏牌下。

2. 左上角小房子，左边距与上边距相同，点了回首页。单人同样有，弹窗或「含无解题」说明打开时不响应；未结算回首页只清连胜、不加失败。双人：显隐与打开弹窗前一致。答题，以及由答题进入的成功、失败弹窗里隐藏；等待抢答和答案弹窗里显示。弹窗打开时不响应。

点小房子回首页：本场状态彻底结束（比分、答题方、交接倒计时都不保留）；再进「双人对战」从 `0 : 0` 开始；累计胜利局数和胜利场数保留；未结算的这一轮不加统计。

比赛结束后若要回首页：先点「再来一场」，再点小房子。

## 2. 等待抢答

新题发出后：

1. 两个抢答按钮同时显示。
2. 卡牌和运算符不能操作。点了就在场上提示「请先抢答」。
3. 显示「下一局」和「显示答案」。
4. 隐藏「重试」和「本题无解」。
5. 显示难度入口，可修改。
6. 显示小房子。
7. 先收到的、命中某一侧抢答按钮的有效触摸取得答题权。一方锁定后，另一方后续触摸不能覆盖。不做「同时请重抢」弹窗；同一事件多个触点时以程序收到的第一个有效触点为准。不出现双方同时进入答题。

# 五、答题模式

手点「抢答」，或第一位失败交接结束后，进入答题模式。

1. 答题方的抢答按钮变成倒计时，文字是剩余秒数。
2. 对方的抢答按钮隐藏，不能点。
3. 卡牌和运算符可以操作。
4. 显示「重试」。打开了「含无解题」时同时显示「本题无解」。
5. 隐藏「下一局」。不画底栏的「显示答案」、难度和「设置」。
6. 难度入口随底栏一起不画。
7. 倒计时按钮下方显示「点击认输」。点倒计时按钮就是认输。第一位、第二位都可认输。
8. 隐藏左上角小房子。回到等待抢答后再显示。由答题进入的弹窗里也保持隐藏。

红方答题时大致是：

```text
     20           3 : 1
  点击认输
```

倒计时：

1. 使用这次答题开始时读到的秒数。
2. 每秒改一次数字。
3. 每次更新，按钮缩小到 80% 再恢复，做一次心跳。按钮仍是原来的圆角矩形。
4. 数到 0 时不显示 0，也不播放心跳，直接判定这次作答失败。

## 倒计时临界点

以最后一次有效操作发生的时间为准，不以动画结束时间为准。

1. 若点击发生时尚未超时，并且这次计算得到 24，则判成功。
2. 若点击发生前已经到达截止时间，则判超时。
3. 合牌动画是否播完不影响判定。

## 切后台

本期不专门处理。切到微信后台再回来时，倒计时按墙钟继续走，可能直接超时。记入 [test.md](test.md)，以后再讨论是否暂停。验收要求：切后台超过剩余时间再返回时，能正常走超时失败流程，不卡在倒计时按钮，也不重复弹窗。

# 六、答题操作

## 1. 重试

只在答题模式显示。点击后：

1. 恢复本题最初的四张牌。
2. 清除当前选牌和运算步骤。
3. 倒计时继续，不重新计时。第一位、第二位都一样。
4. 不改变比分和统计，不算成功或失败。

## 2. 本题无解

同时满足才显示：已开启「含无解题」，并且正在答题。退出答题模式后自动隐藏。

1. 判断正确：当前玩家答题成功。
2. 判断错误：当前玩家这次作答失败。

## 3. 下一局

只在非答题状态显示，弹窗里的「下一局」除外。点击后：

1. 直接开始下一题。
2. 不改变比分。
3. 不记录成功或失败。
4. 双方重新进入等待抢答。
5. 当前题不会再恢复。

## 4. 显示答案

只在非答题状态显示。按钮文字是「显示答案」。单人模式仍叫「答案」，并且仍在对局页面展开。

双人点击后不在对局页面显示答案，改为弹窗：

1. 标题：「答案」
2. 文本：本题的答案。有解题用现有 `expression`；无解题为「本题无解，无法算出24」。
3. 按钮：「下一局」。点了就发下一题，比分保留，不计成功或失败。

弹窗打开时，只登记弹窗内按钮。这题不能再抢答得分，也不能关闭答案继续抢。不改变比分或统计。答案弹窗不铺整页遮罩：牌、抢答、底栏和打开前已经显示的按钮继续画着，外层点击不响应。答案仍只写在弹窗里。

# 七、第一位玩家失败

失败包括：最后结果不是 24、错误判断「本题无解」、超时、点倒计时按钮认输。认输、答错、超时走同一失败流程。

弹窗两行：

```text
很遗憾，本次作答没有成功。
3秒后由对手继续答题。
```

第二行每秒改为「2秒后由对手继续答题。」「1秒后由对手继续答题。」到 0 秒时不显示「0秒」，直接关闭弹窗。

按钮是「开始答题」。点了就不用等满 3 秒。

自动倒计时结束与点击「开始答题」同时触发时，只执行一次。

交接完成后：

1. 恢复本题最初的四张牌。
2. 对手自动进入答题模式，不用再抢。
3. 对手获得一段完整的答题时长。

双方都不记失败统计。弹窗打开时清空对局 `hits`，只登记弹窗按钮。

# 八、第二位玩家失败

第二位答错、超时或认输后，弹窗两行：

```text
很遗憾，本次作答没有成功。
本局结束。
```

按钮只有「下一局」。不显示参考答案，也没有参考答案按钮。双方都不得分，也不记录失败。点「下一局」后比分保留，进入下一题的等待抢答。

# 九、答题成功

成功条件：四张牌用完且最终结果精确等于 24，或正确判断「本题无解」。

成功后当前玩家比分 +1，胜利局数 +1。对方不再答题。

1. 未到 5 分：文本「太棒了，本局获胜！」按钮「下一局」。
2. 已经到 5 分：改走第十节，不再弹这一则。

# 十、比赛结束

某一方这次成功后率先达到 5 分，本场结束。这次成功已经加过胜利局数，再给获胜方胜利场数 +1。同一成功只加一次胜利局数和一次胜利场数。

文本：「太棒了，本场获胜！」

只有一个按钮「再来一场」：本场比分回到 `0 : 0`，保留难度、「含无解题」、答题时长和累计胜利局数、胜利场数，新发一题。回首页：再来一场之后点小房子。

# 十一、双人统计

设置页在单人「对局统计」下面放「双人对战」。只统计胜利局数、胜利场数（红蓝各记）。不统计失败、超时、认输、连胜、成功率。不影响单人统计。没有清零按钮，清缓存才归零，答题时长也回到 20 秒。

短屏布局：双人统计用两行两列紧凑表，答题时长放在该卡片之外（减 / 秒数 / 加，每次 ±5）：

```text
双人对战
          红方   蓝方
胜利局数   18     14
胜利场数    3      2

双人对战答题时长    −  20  +
```

# 十四、验收标准

1. 首页有「单人游戏」和「双人对战」。
2. 双人答题时间用加减按钮（每次 ±5）设为 10 到 60 秒，默认 20 秒。
3. 与单人相同的底栏与底栏上方按钮，位置一致；卡牌下方另有「红方抢答、比分、蓝方抢答」，抢答区预留「点击认输」行高。
4. 未抢答前不能操作卡牌。
5. 抢答后只显示当前玩家的倒计时按钮，每秒心跳缩放，到 0 直接失败。
6. 真机近乎同时点红蓝时，先收到的一方取得答题权；锁定后另一方不能覆盖；不出现双方同时答题。
7. 点击倒计时按钮可以认输。
8. 重试恢复四张牌，但不重置倒计时，也不改比分和统计。
9. 本题无解只在开关打开且正在答题时显示。判对算成功，判错算这次失败。
10. 「下一局」和「显示答案」只在非答题状态显示。双人点「显示答案」弹出标题为「答案」的窗口，对局页不展开答案，按钮是「下一局」，这题不能再抢答得分。
11. 第一位失败后，3 秒后自动轮到对手，也可以提前开始。对手从原始四张牌和完整时长开始。
12. 第二位失败后本局结束。弹窗只有失败说明和「下一局」，没有参考答案，比分不变。
13. 答对加 1 分和 1 次胜利局数。未到 5 分的文案是「太棒了，本局获胜！」
14. 先得到 5 分增加 1 次胜利场数。文案是「太棒了，本场获胜！」，弹窗只有「再来一场」。回首页：再来一场后再点小房子。
15. 双人左上角小房子：答题，以及由答题进入的弹窗里隐藏。等待抢答时可点回首页，本场彻底销毁。答案弹窗里显示但不响应。
16. 等待抢答时改难度或「含无解题」立即换题，比分不变。
17. 双人题库、难度、含无解题和统计与单人分开。
18. 双人模式不记录失败。
19. 合牌判定以有效点击时刻为准，不以动画结束时刻为准。
20. 切后台超过剩余时间再返回，能正常超时失败，不卡住、不重复弹窗。

# 十五、技术实现

逻辑放在 `js/game/`，不引用 `wx`。场景只翻译点击、画动画、读写存储。不把仓库收成 `packages/` 或 `apps/wechat-game`。

## 1. 纯逻辑

1. 新增 [js/game/session.ts](../js/game/session.ts)。把 [js/scenes/play.ts](../js/scenes/play.ts) 里的选牌收成 `selectCard`、`selectOp`、`restart`。合牌仍调用现有 `merge` 和 `outcome`。单人改走这一层，动画、音效和单人统计仍留在场景，单人表现不变。
2. 新增 [js/game/duel.ts](../js/game/duel.ts)。阶段为 `thinking`、`answering`、`handoff`、`revealed`、`roundEnd`、`matchEnd`。
3. 状态记下第一位、当前答题方、红蓝本场分数、答题截止时间、交接截止时间，以及是否已打开答案。
4. 命令都接收调用方传入的 `now`，模块内部不读 `Date.now()`。命令包括 `buzz`、`timeout`、`resign`、`succeed`、`startSecond`、`retry`、`revealAnswer`、`nextRound`、`rematch`、`setFilter`、`setIncludeUnsolvable`。
5. 目标分固定为 `DUEL_TARGET = 5`。时长由参数传入；设置页步进为 5 秒。
6. `retry` 只重置牌面和选牌，不改截止时间。
7. 第一位失败进入 `handoff`，不改分数和统计。`startSecond` 把牌重置为原题，并给对手一段完整时长。
8. 第二位失败进入 `roundEnd`，分数不变。
9. 成功时该方分数和胜利局数 +1。达到 5 分则再加胜利场数，阶段改为 `matchEnd`。
10. `revealAnswer` 进入 `revealed`。双人只打开答案弹窗，不把答案画在对局页。之后 `buzz` 无效，弹窗里的「下一局」调用 `nextRound`。
11. `setFilter` 与 `setIncludeUnsolvable` 都只能在 `thinking`：保存双人设置、立即换题、比分不变、回到等待抢答。
12. 胜利统计的加减是纯函数 `(stats, event) => stats`。
13. 超时判定在处理点击或 `tick` 时用传入的 `now` 与截止时间比较；合牌成功与否在点击处理路径上立刻判定，不靠动画回调。

## 2. 场景、绘制和存储

1. 单人继续用现有 [js/scenes/play.ts](../js/scenes/play.ts)。双人新增独立场景，例如 [js/scenes/duel.ts](../js/scenes/duel.ts)，共用 `session`、合牌、抽题与绘制辅助，不把双人状态机塞进 `PlayScene`。
2. 双人场景负责发牌、合并、心跳和弹窗。秒数变化时播一次缩放。弹窗打开时清空对局 `hits`，只登记弹窗按钮。
3. 发牌仍调用现有 `pickPuzzle`，传入双人自己的已玩集合、难度和「含无解题」。
4. [js/settings.ts](../js/settings.ts) 用 `wx` 分开存放：双人难度、双人「含无解题」、双人已玩 id、答题秒数、`duelStats`。这里只读写，不判断胜负。
5. 答题时长用加减按钮写入，每次 ±5，夹在 10 到 60。
6. [js/main.ts](../js/main.ts) 区分单人和双人入口。从对局打开设置再返回时，回到原来的模式。回首页销毁当前双人场景实例。
7. [js/scenes/settings.ts](../js/scenes/settings.ts) 在单人统计和音效之间：双人两行两列统计表，其下单独一行答题时长（减 / 秒数 / 加）。

`duelStats` 四项：

1. 红方胜利局数
2. 蓝方胜利局数
3. 红方胜利场数
4. 蓝方胜利场数
