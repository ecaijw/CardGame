# 24 点 — 产品需求

用 4 个数玩经典 24 点的微信**小游戏**。玩法以 [rules.md](rules.md) 为准（已冻结）。本文只写页面、分期和验收。实现边界见 [roadmap.md](roadmap.md)，技术见 [tech.md](tech.md)。

## 1. 第 0 期测试牌

第 0 期界面只显示数字、不画花色。测试牌写死、三组循环：

- `1, 2, 3, 8`（例如 `8÷(3-2)×1` 的等价合并，或 `8×(3-2)×1` 等；实现时保证有解即可）
- `3, 3, 8, 8`
- `1, 5, 5, 5`

## 2. 页面

### 2.1 首页（第 0 期）

- 标题展示登记名「数字算一算」（备案截图须与当前小游戏名一致）。介绍两行：四张数字卡片，算出 24 / 来挑战一下。
- 第 2.2 期起首页按钮为：单人游戏、双人对战、游戏说明、设置。「单人游戏」即原「开始游戏」。
- 单人游戏：进入对局。第 0 期从 3 组测试牌取第一组或上次「下一局」之后的下一组。第 1 期起从题库抽有解题（优先未玩）；从首页再进则重置当前题，不另抽。
- 双人对战：见 [phase-2.2-duel.md](phase-2.2-duel.md)。进入一场新的 `0 : 0`。
- 游戏说明：在「设置」上方，进入说明页
- 视觉规范见 2.6。标题上方展开 4 张暖白数字卡（示例 `1, 2, 3, 8`，简单有解题），每张数字可见。
- 第 2 期起右下角「设置」（齿轮图标 + 文字），进入设置页。

第 1 期起可在首页增加难度入口。第 2 期起可增加统计入口。第 3 期起可增加去广告入口。

### 2.2 说明页（第 0 期）

用短文概括 [rules.md](rules.md)：4 张牌各用一次、点两张牌再点运算符合并、目标是场上只剩 24。不写算法细节。

### 2.3 对局页（第 0 期）

- 4 个数字方块（接近扑克长宽比），固定 2×2 格子。合成牌占后点那张的格子，先点的格子留空，不按剩余张数重排。
- 运算符：`+ - × ÷`
- 操作：重开本局、下一局。第 1 期起左下角「查看答案」；底部中间难度筛选（默认简单）。第 2 期起右下角「设置」。
- 选中态：已选第一张牌、已选运算符时，界面能看出来
- 非法操作忽略并给轻量反馈（例如只选了一张就点等号类操作：本产品没有等号，未选满两张牌就点运算则忽略或提示）

交互顺序（推荐）：

1. 点第一张牌
2. 点运算符
3. 点第二张牌
4. 两张牌从场上拿走，放入一张值为运算结果的新牌
5. 若场上只剩一张：等于 24 则成功，否则失败。重开不记失败。未结算就下一局、换难度、看答案或回首页不记失败，但清连胜。

除数为 0 时该步不得执行，场上不变并提示。场上多于一张时，即使某张已是 24，也不弹成功。

### 2.4 结果（第 0 期）

仅在场上只剩一张牌时弹出成功或失败，不必单独页面。

- 成功：可「下一局」
- 失败（不等于 24）：可「重开本局」或「下一局」
- 重开：立刻重置本局，不弹失败，不改连胜
- 下一局：切换题目；若本局尚未结算则清连胜，不记失败

第 0 期不做「看答案」「无解」。

### 2.5 后续页面（非第 0 期）

| 页面 | 起始期 | 内容 |
| --- | --- | --- |
| 难度选择 | 1 | 对局底部中间，默认简单，可选中等 / 困难 / 全部 |
| 提示 | 1 | 左下角「查看答案」，显示完整表达式 |
| 统计 | 2 | 设置页：总数（发牌计 1 局）、成功 / 失败以本局最后一次结算为准、连胜 |
| 设置 | 2 | 首页 / 对局右下角进入；音效、音乐开关（默认开，音源已接） |
| 去广告 | 3 | 1 天 / 终身 两档 |
| 每日一题 / 排行 / 成就 | 4 | 见路线图 |

### 2.6 菜单 UI 规范（首页 / 说明页）

对局页背景与首页相同（薄荷绿渐变 + 丘陵）。对局按钮默认暖白；点中后才出现浅珊瑚底和珊瑚字。牌面数字仍是珊瑚红。重开 / 下一局贴近底部工具条，避免误触运算符。下列约束首页和说明页的标题、卡片与按钮，以设计稿为准；不要再做成红字黄底。Canvas 自绘，不铺整页背景图。植物、阴影、渐变用规则化参数，不逐像素描稿。

**视觉层级**

醒目标题 > 数字卡片 > 开始游戏 > 副标题和游戏说明。

**适配**

- 顶部卡片根据 `wx.getMenuButtonBoundingClientRect()` 的胶囊下沿再往下让 28px，不用写死坐标
- 标题字号随屏宽约 `min(52, width * 0.14)`

**背景**

- 薄荷绿竖向渐变（浅顶 `#F4FBF6` → 底 `#C5E6D3`）
- 底部两层贝塞尔丘陵 + 椭圆组合叶片，不抢标题

**数字卡片**

- 暖白 `#FFFEFB`，约 1:1.25，圆角约 14，轻阴影 + `#D7EEE4` 浅描边
- 点数珊瑚红 `#F25542`，PingFang SC 800
- 四张横向展开：外侧约 ±7°、内侧约 ±2°，外侧略下沉，互不遮住数字

**标题「数字算一算」**

- 填充珊瑚 `#F25542`；先 `strokeText` 再 `fillText`，描边奶油 `#FFF1D8`（线宽约字号 13%，填后可见约 3px）
- 字重 800；先用 PingFang SC 近似稿里的圆体，不另加未授权字体
- 阴影：向下 3px 浅橙 `rgba(242, 85, 66, 0.2)`
- 无标题色块。黄色只用于两侧 `+` / `×`

**说明文字**

- PingFang SC 400，18px，灰绿 `#4A5C56`
- 两行：四张数字卡片，算出 24 / 来挑战一下

**按钮**

- 首页四个按钮水平居中，宽 280（更窄时缩小），圆角为高度的一半。单人、双人高 64；游戏说明、设置高 56。间距：单人到双人 28，双人到游戏说明 90，游戏说明到设置 20。描边 2px，字号 18。单人从左到右 `#FF8E7D` → `#FF7464`，描边 `#E85A4F`，白字白图标。双人从左到右 `#FF7464` → `#769FED`，描边 `#5F85D8`，白字，左人 `#F25542`、右人 `#4F83E8`。游戏说明和设置底 `#FFFEFB`，描边 `#68B58D`，字 `#24352F`，图标 `#2F6B4F`。按下缩放到 0.97，约 100ms。
- 对局默认暖白底、浅描边、深字；点中后浅珊瑚底 `#FFEDE8` + 珊瑚字 `#F25542`
- 算符用大号圆角方钮；点中浅珊瑚底。重试 / 下一局为半宽胶囊，图标和文字在钮内居中，贴在底部较矮的三格工具条上方
- 底部查看答案 / 难度 / 设置为一条分段栏
- 不要高光条、粗黑边、强拟物阴影

## 3. 各期产品范围

### 第 0 期 — 可玩 MVP

有：首页、说明、对局（3 组测试牌、数字方块、合并、重开、下一局）、成功 / 失败。

没有：求解器全集、难度、提示、统计、音效、扑克图、广告、登录、云存储。

**验收**

- 微信开发者工具按 **Mini Game** 导入后能编译预览
- 三组测试牌都能走完：合并到 24 显示成功；合并错显示失败
- 重开回到本局 4 张初始牌；下一局切到下一组（第三组之后回到第一组）
- 界面只有数字长方形，无扑克花色

### 第 1 期 — 完整数据 · 已完成

- 全量有解题库（离线生成）· 已接入对局抽题
- 对局从题库抽题，优先未玩过的 · 已接入
- 已玩记录仅存在用户本地，按题目 id · 已接入
- 提示：对局左下角「查看答案」，显示完整表达式 · 已接入
- 难度筛选：右下角，默认简单，可选中等 / 困难 / 全部 · 已接入

**验收**

- 不会抽到无解四元组
- 每题能展示至少一种逐步解法
- 重装小游戏后题库仍在（打进包内）；已玩记录可清空（清缓存）

### 第 2 期 — 细节和美化 · 已完成

设置页：对局统计（发牌计总数；成功 / 失败以本局最后一次结算为准；连胜）、音效开关、音乐开关。基础牌面动画已接入，见 [animation.md](animation.md)。音源与播放已接，见 [audio.md](audio.md)。数字 / 扑克已改列入后续。未结算时下一局 / 看答案 / 换难度 / 回首页会清连胜，不加失败；重开保持连胜。统计清零见 [test.md](test.md) 第 11 条，已 `won't fix`，仍靠清缓存。

交接见 [phase-2-handoff.md](phase-2-handoff.md)。

### 第 2.1 期 — 上线 · 进行中

不是第 3 期。把当前可玩版本完成上线：游戏类目、资质、备案、提审、发布。登记名「数字算一算」，备案截图须与小游戏名一致。

过程中可以修小问题、做体验优化（例如 [test.md](test.md) 里仍 open 的布局与统计确认项）。先讨论再改代码。

对局宽屏未显示答案时，答案区域显示与设置页相同的对局统计（总数、成功、失败、连胜）。普通宽度不显示这块统计。显示答案或错误提示时，换成同样的圆角卡片。宽屏整块在顶部留白和贴底之间偏上。

难度菜单在四个难度之上有「含无解题」，默认关。难度和这个开关都会记住，清缓存才恢复默认。每次打开时居中说明，只有「关闭」能关掉，并且不重发当前这题。打开之后，每次发牌有 25% 的机会是无解题，其余仍是当前难度的有解题。两个池子各自优先未玩过的题。对局在「重试」和「下一局」中间显示「本题无解」。判断正确走成功；判断错误走失败，并说明这题可以算出 24。点「本题无解」时，场上剩下的牌仍留在原来的格子里。已经打开这个开关时，算到一张牌但不是 24 的失败说明改为：如果有解，最后结果需要算出 24；如果无解，点击「本题无解」。无解题的答案显示「本题无解，无法算出24」。发牌、成功、失败仍按现有结算规则。同一局先失败再成功时，连胜从 1 开始。

本期没有新页面。不接广告、不接支付、不用云。数字 / 扑克仍属后续。

交接见 [phase-2.1-handoff.md](phase-2.1-handoff.md)。

### 第 2.2 期 — 同机双人对战 · 已完成

同一设备双人抢答。详细产品、界面状态与验收见 [phase-2.2-duel.md](phase-2.2-duel.md)。要点：先抢答再限时合牌；第一位失败后换对方；先到 5 分获胜；双人题库 / 难度 / 统计与单人分开；设置页可调答题时长（默认 20，每次 ±5，10～60）。单人和设置页宽屏仍从 748 起左右分栏。双人布局已在第 2.3 期改为竖屏居中单列、横屏先试三栏，见 [ux/issue-49-responsive-layout.md](ux/issue-49-responsive-layout.md)。

交接见 [phase-2.2-handoff.md](phase-2.2-handoff.md)。

### 第 2.3 期 — 响应式布局 · 已完成

首页、单人和双人按 [ux/issue-49-responsive-layout.md](ux/issue-49-responsive-layout.md) 重排。双人竖屏居中单列，横屏先试三栏，排不开再退回单列。设置页保持第 2.2 期的样子。844×390 不纳入本期。难度菜单用带描边的卡片托住选项：单人和双人居中单列仍在按钮附近并夹在屏幕内，双人三栏从按钮右侧展开。

交接见 [phase-2.3-handoff.md](phase-2.3-handoff.md)。

### 第 2.4 期 — 体验收口 · 进行中

第 2.3 期之后的体验收口，并上线当前版本。领先一方在比分旁边显示与成功弹窗相同的小皇冠，红方领先在红分右边，蓝方领先在蓝分左边，高度是比分的 80% 并垂直居中；小房子竖屏按顶部安全区下移、横屏按左侧安全区右移来避开前置摄像头，不跟着牌桌下移，牌桌位置不变。上线仍是游戏类目、资质、备案、提审、发布，登记名「数字算一算」。不改玩法，不接广告和支付。切后台暂停倒计时和双人「下一局」确认本期不做。

交接见 [phase-2.4-handoff.md](phase-2.4-handoff.md)。

### 第 3 期 — 广告和收入

- 免费用户每 20 局看一次广告
- 简单难度免费；进入中等或困难时，免费用户看一次激励视频，已购去广告则跳过
- 虚拟道具：0.99 畅玩 1 天；9.90 终身畅玩。不做用户自填金额

### 第 4 期 — 社交与留存

每日一题（本地日期种子）、分享到聊天、云开发排行与战绩、好友异步挑战、成就与牌面主题。

### 后续

数字 / 扑克显示切换（[test.md](test.md) 第 12 条已 `won't fix`，上线后再看用户反馈）、云对战、英语、网页 / App、自定义赞赏（若政策允许）。
