## 3. 核心算法

### 3.1 分数（第 0 期）

所有中间结果用整数分子 / 分母存储，不做约分。允许 0 与负数。显示规则见 [rules.md](rules.md) 第 2 节。

- 加、减、乘按常规分数运算
- 除：除数为 0 则该步失败，不改场上牌
- 成功：`分子 === 24 × 分母`（未约分也可以，如 `48/2`）
- 显示：能整除则显示整数，否则不约分

禁止用 `number` 直接 `=== 24` 作为终局判定。

### 3.2 合并与撤销（第 0 期）

场上是一张牌的列表。每张牌含：

- `id`：本局内唯一（合并新牌用新 id）
- `value`：分数

一次合法合并：选 `a`、运算符、`b` → 删除 `a` 与 `b`，结果牌占用 `b` 的格子。

撤销栈保存合并前的牌列表快照（或逆操作）。重开本局 = 恢复本局初始 4 个数。

### 3.3 第 0 期题库

`puzzles.fixture.ts` 写死三组，例如：

```ts
{ id: "1,2,3,8", nums: [1, 2, 3, 8] }
{ id: "3,3,8,8", nums: [3, 3, 8, 8] }
{ id: "1,5,5,5", nums: [1, 5, 5, 5] }
```

「下一局」按数组下标循环。不调用求解器。

### 3.4 全量题库（第 1 期）

电脑上跑 `scripts/generate-puzzles.ts`：

- 枚举 1–13 的四元组（可重复、与顺序无关，约 1820 种）
- 用分数穷举逐步合并，筛出至少有一解的条目
- 写出 `miniprogram/game/puzzles.json`，提交进仓库
- 运行时只读该文件，设备上不再穷举

条目形状：

```ts
{
  id: string
  nums: [number, number, number, number]
  difficulty: "easy" | "medium" | "hard"
  steps: string[]       // 与合并 UI 一致，如 ["8÷2=4", "3×4=12", "1×12=24"]
  expression: string    // 给「看完整解法」
}
```

难度在生成时写入（解的个数、是否需要除法 / 括号、是否含 11–13 等）。运行时只读字段。

提示：一步用 `steps[0]`，完整用 `steps` 或 `expression`。题库已保证有解，不必再判断「是否有解」。

已玩记录：**不要**写进 JSON。用 `wx.setStorage` 存题目 id 集合。

体积预期：千余条加解法字符串，约几十到一两百 KB，可打进小程序包。

## 5. UI 与资源

- 单位：逻辑像素（`windowWidth`），竖屏
- 第 0 期：Canvas 长方形 + 数字，比例接近扑克（约 63:88）
- 第 2 期：自绘 4 花色 × 13 点，避免版权图；显示模式可切换
- 动画：第 2 期再加

## 6. 广告与支付（第 3 期，第 0 期不实现）

- 广告：`wx.createRewardedVideoAd`、`wx.createInterstitialAd`，需开通流量主
- 免费用户每 20 局一次广告；进中等 / 困难时激励视频一次（已购去广告则跳过）
- 去广告 SKU：0.99 一天、9.90 终身。终身清缓存后须能凭订单恢复
- 不做用户自填金额

第 3 期走小游戏流量主与米大师；收费档需企业主体，是否要版号以当时开通虚拟支付的规则为准。

## 7. 云开发（第 4 期）

每日一题仍可用日期种子本地选题，不必上云。排行榜、战绩同步、好友挑战再用云函数和数据库。分享用 `onShareAppMessage` 带题目 id。
