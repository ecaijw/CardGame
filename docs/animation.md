# 24 点 — 牌面动画

第 2 期「基础牌面动画」的参考记录与方案。玩法仍以 [rules.md](rules.md) 为准（已冻结）。页面与验收见 [prd.md](prd.md)，实现边界见 [tech.md](tech.md)。

**状态（2026-09-21）：** 对局手感、发牌回弹、结算闪金/轻抖已接入 `js/scenes/play.ts`。参考片是本地录像 `24CardGame_ref.mp4`（约 45s，竖屏，未入库）。

原则：**休闲小游戏该有的反馈要有，不要做成参考片的仿版。** 合成牌仍占后点格子，先点格子留空，固定 2×2 不重排。参考片用来判断「这类游戏会动哪里」，不作为动作清单去对齐。

## 1. 参考片里有什么（记录，不照搬）

真正有牌感的是约 12–45 秒的对局。前面首页、角色闯关、关卡网格可以忽略。

操作顺序与我们相同：**第一张牌 → 运算符 → 第二张牌**。

### 1.1 时间线（对局段）

| 约秒 | 画面 |
| --- | --- |
| 11.4–12.1 | 进入「高中生 2/20」，先 4 个空薄荷底，数字错开淡入：`2, 2, 3, 4` |
| 16.0–16.8 | 点选 `4`（底色加深、略放大），再点 `+`（橙底白符号） |
| 16.9–17.2 | `4` 滑向右上 `2`，重叠半透明，落点弹出 `6`；右下格变空；`6` 保持选中 |
| 17.7–18.0 | 点 `+` 后再点左上 `2`，`6` 滑向该格，弹出 `8` |
| 18.4–19.0 | 点 `×` 后再点 `3`，`8` 滑向该格，落点变成橙色 24 徽章 |
| 19.0–20.1 | 24 徽章从落点滑到棋盘中央，再出结算层：「完美!」+ 题库表达式 +「下一题」 |
| 21.2–21.8 | 下一题发牌，同样空底 + 错开淡入：`12, 6, 4, 9` |
| 23.6–25.6 | `6÷?` 走成中间 `24`（仍是普通牌，因为场上还有 `9`），再 `24÷9` |
| 25.6–26.9 | 最后一张不是 24：落点出现上下分式 `24/9`（灰绿），再滑到中央，文案「得到 24 才算答对哦」 |
| 27.2–27.8 | 点「重来」，同一题再发一遍 |
| 40–45 | `(12-4)×(9-6)` 成功，结算文案换成「太棒了!」 |

第一局玩家实际路径是 `4+2→6`，`6+2→8`，`8×3→24`。结算上的表达式是题库解 `(2×2+4)×3`，**不是玩家刚才那条路径**。

### 1.2 它动了哪些环节

发牌空底淡入、点选放大、先点牌飞向后点牌、结果弹出、末牌滑到中央再结算、重来再用同一套发牌。规则层（后点占格、空位不重排、中间 24 不结算）与我们已经一致。

这些动作能说明「合并、发牌、结算值得给反馈」，但飞牌吞噬、空底填字、24 徽章巡礼是那款产品的招牌，我们不用。

## 2. 方案

缺的是轻反馈，不是另一套表演。当前对局是瞬切：两张消失、结果立刻出现在后点格；发牌 / 重开 / 下一局下一帧画齐；成功 / 失败立刻盖遮罩。`main.ts` 已有每帧重绘，对局场景还没有时间轴。

设计目标：点下去有弹性、合并能看出「两张变成一张」、进出场不闪、结算有一下轻奖/轻挫。整段锁操作尽量短，连续合并不要等。

### 2.1 点选

- 牌：保留金色描边；短弹簧放大约 `1.0 → 1.06`，阴影略加重，像被拿起。再点同一张则缩回并取消选中。
- 运算符：保持现有浅底 + 金边；点中时轻按压缩放（约 `0.96 → 1`）。
- 未选牌就点运算：继续 toast；运算按钮横抖一下。

### 2.2 合并（飞过去叠在一起再弹出）

点第二张且合并合法后，先点那张**快速飞到后点格中心重叠**，再弹出结果，类似合并小游戏。中间不要画运算符。

1. 短暂锁定点击（飞约 220ms + 弹出约 320ms）。
2. 飞行中后点那张停在原格、不做缩放，并盖在先点那张上面；先点那张用 ease-out 从下方滑到后点格中心。
3. 先点那张到位后，后点格换成结果牌：牌从约 `0.94` 用 ease-in-out 弹到选中尺寸（约 1.04；结算局到 1）。数字单独从约 `0.8` 用 ease-out 收到 1。
4. 对局未结束：结果牌保持选中，运算符清空。先点格留空，不重排。
5. 除以 0 或不合法：不播动画，场上不变，只 toast。

逻辑仍先算 `merge` 结果，画面再播这段。`js/game/merge.ts` 的规则不用为动画改。

### 2.3 发牌 / 重开 / 下一局

不要先铺 4 个空底再填数字。四张都在**自己的格子里轻微放大到位**，不要从上往下落，也不做透明淡入。

- 四张同时约 320ms，牌轻微放大（约 0.96→1），中间数字单独缩放且幅度大约是牌的 3 倍，不改透明度。
- 对局中重开 / 换题：旧牌先轻微缩小再换新牌。结算弹窗点「下一局」或「重开本局」时，中央那张结果牌立刻消失，不要回到原格再缩小。
- 不要切场景闪白。

### 2.4 结算

仍用现有遮罩弹窗（成功：下一局；失败：重开本局 + 下一局）。最后一张**停在后点格**，不要滑到屏幕中央。弹出结算时仍清空对局 `hits`，只登记弹窗按钮。

**成功：** 最后一张滑到 2×2 棋盘矩形中央（约 560ms），金色描边 + 金环和 6 个金点跟着牌走、节奏放慢。弹窗顶部落在最后一张牌底边与运算符按钮顶边的中点。整页同一层遮罩，最后一张牌画在遮罩之上、仍停在棋盘中央。文案是「成功 / 太棒了，继续挑战吧！ / 下一局」。失败是「失败」加两行说明（成功条件：最后结果是24。 / 加油再试一试吧！）。标题左侧用设计稿裁出的 PNG（`icons/crown.png` / `icons/fist.png`），约标题字号的 70%。

**失败：** 同样滑到棋盘中央，不要左右抖动。牌一到位就出失败层（不必等成功那套闪光），弹窗同样顶对齐牌底与运算符之间的中点。

### 2.5 节奏

合并先飞约 220ms，再弹出约 320ms（与发牌展开同长）。发牌在各自格子展开。结算先把牌移到中央（约 560ms）；成功闪光整段约 780ms 再出弹窗，失败牌到位即可出窗。

| 动作 | 时长 | 缓动 |
| --- | --- | --- |
| 点选放大 | 180ms | ease-out，约 1.04 |
| 源牌飞到后点格 | 220ms | ease-out，从下方飞到中心重叠；后点牌途中不动、画在上面 |
| 结果弹出 | 飞完后 320ms | 牌 ease-in-out，0.94→选中 1.04；数字约 0.8→1 |
| 发牌展开 | 四张同时 320ms | ease-out，0.96→1，不改透明度 |
| 末牌移到棋盘中央 | 560ms | ease-out |
| 成功闪金 | 与移牌重叠，整段约 780ms | — |
| 结算弹窗出现 | 220ms | ease-out |

## 3. 实现要点

- 动画状态放在 `js/scenes/play.ts`，不要改 `merge` 规则。建议状态：`idle` / `dealing` / `merging` / `settling`。
- 用已有 `requestAnimationFrame` 循环驱动；对局 `draw` 读时间戳做插值。
- `merging` 时源牌按缩放/透明度画在原格，结果牌在后点格弹出；不要做跨格插值。
- `dealing` / `merging` / `settling` 期间忽略对局点击（结算弹出后仍只登记弹窗按钮）。
- 结算弹窗顶对齐最后一张牌底边与运算符顶边的中点；整页遮罩，最后一张牌画在遮罩之上。
- 非法合并不进动画状态。
- 金点只在成功结算画几个圆，不要引入动画库。

---

## 4. 建议工期

1. **对局手感：** 点选缩放 + 飞牌重叠再弹出结果 + 非法操作轻抖。
2. **进出场：** 各自格子展开发牌；重开 / 下一局先淡出再发。
3. **结算：** 最后一张滑到 2×2 中央；成功闪金；弹窗顶对齐牌底与运算符之间的中点。

---

## 5. 不做

- 先点牌飞向后点牌、重叠半透明。
- 发牌先出空底再淡入数字。
- 橙色徽章、齿轮形 24。
- 「完美 / 太棒了」、闯关升级、页内失败提示替代弹窗。
- 把结算表达式改成玩家现场路径（继续用该题 `expression`）。
- 为动画改格子规则。
